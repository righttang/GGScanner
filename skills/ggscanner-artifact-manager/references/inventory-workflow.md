# 库存、配装和预算流程

## 基线

记录扫描时间、客户端语言、HDR、客户区尺寸和扫描选项。确认需要的角色/武器/
圣遗物分类全部完成。低星级、定义圣遗物及“仅五星获得时间”筛选影响库存范围。
失败、停止或部分导出不能作为全量基线。

原始 GOOD 不覆盖，另外保存工作副本。检查分类数量、角色实际等级/命座/天赋，
以及武器精炼/等级/持有人。OCR 错误先修正或标记，不补造属性。打造新增物品、
精炼减少副本时，原始计数与最终计数分别记录。

## 分配

通过 GGArtifact 正常导入 GOOD 并保留用户配置。按用户角色范围、优先级和独立
约束分配；网站无法给出的方案，用剩余库存建立明确标注的过渡组合。

本地校验每人五个不同部位，角色存在且符合用户门槛。禁止共用时，库存索引互不
重复。再按服务器身份匹配规则在整个库存检查碰撞：套装、部位、星级、等级、
主词条、副词条及未激活词条、`elixirCrafted`，属性容差为0.1。持有人、锁定与
星标不能用于正式匹配消歧。无法唯一识别的副本先观察或单独处理。

根据角色定位检查主属性、套装与充能循环。按当前版本资料核对新角色、星/月反应、
天赋归属、实装命座和武器触发者，不能用过时印象判断双暴或精通价值。
词条或武器特效对比不是完整队伍伤害模拟。

网站导出计划不等于已应用到游戏；独立浏览器资料导入也不代表其他浏览器同步。

## 预算台账

记录用户授权的动作、总量、每件/每次上限、允许消耗的材料及已用/剩余。
强化、打造、重塑、精炼分别计数，计划/提交/观察/核验分别标记。

强化前排除已分配和保留的材料。分阶段升级再评价，不自动把所有候选拉满。
自动添加预览可能选到三星武器或五星圣遗物；类型不符授权则取消并手动选经验材料。
有足够经验材料不意味着应清空未锁定库存。

打造使用祝圣之霜，重塑使用启圣之尘。名称不明确且影响提交时先核对动作与消耗。
重塑结果按完整配装比较，不只看暴伤；保留旧词条也计一次，不能追加免费尝试。

锻造前查已有成品、闲置副本与实际队伍机制。精5需五把同名副本，只有主成品需
升级。分别列配方总量、可低阶合成的数量和实际缺口。高等级、已装备、稀有或
独立角色仍需使用的武器不因重名就消耗。换武器释放旧成品后重新排培养优先级。

## 应用和核验

备份原配装后再提交 `/equip` 或 `/manage`。按当前 `jobId` 读取每条结果，区分
`success`、`already_correct`、`not_found`、`ui_error`、`aborted`。停止后的未执行
条目不能直接解释为库存不存在，记录真实完成项再处理余项。

可重新扫描，或用完整基线加受控变更及正式流程回执核验所有变更位置。后者明确
说明未变更位置沿用基线，不能称为重新全扫描。检查实际持有人、五部位、独立性、
角色范围、物品属性和预算，最后把实际状态导回网站核对，避免导入未执行的计划。

## 队伍预设

确定要修改游戏、GGArtifact 或两者。可先完成方案和备份，依赖目的地的操作才
等待该答案。网站格式测试成功不能作为用户当前预设已被替换的证据。

备份旧队名、槽位和成员顺序。容量以游戏 UI 为准，超出部分另存。GGArtifact
使用其生产导入格式和内部角色/武器/套装 ID，不直接假设 GOOD key 等于网站 ID。
导入会直接修改本地存储时，用隔离资料验证。

先验证一队。重新进入选择器可能重置筛选；应用筛选可能重排已选成员，而选择时
不立即重排。确认“清除筛选”实际存在后才点击，避免同坐标误选头像。
保存后逐槽读取名字，不能凭仍显示旧队的背景模型判断。队名有独立长度限制，
保存后重读；当前出战队伍模型加载可能更慢。

预设可复用角色；多队同时出战时另查角色无交集。常用、变体和培养中队分开说明，
附操作提示和未完善的武器/天赋。
